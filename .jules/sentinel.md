## 2024-05-29 - Hardcoded CORS Wildcard
**Vulnerability:** The `account-deletion` Edge Function used `Access-Control-Allow-Origin: "*"` in its CORS configuration. This is overly permissive and can lead to unauthorized domains making cross-origin requests, potentially bypassing security controls if sensitive data is handled or if authentication relies solely on cookies (though Edge Functions typically use Bearer tokens).
**Learning:** Hardcoded wildcard CORS headers (`*`) defeat the purpose of Same-Origin Policy protections. While it might be convenient during early development, it poses a security risk in production environments.
**Prevention:** Always implement dynamic CORS validation. Verify the incoming `Origin` header against a whitelist of trusted domains (e.g., your app's production URL and local development URLs). If the origin is allowed, set `Access-Control-Allow-Origin` to that specific origin. Also, include `Vary: Origin` to ensure intermediate caches handle responses correctly based on the requesting origin.
